# 转向器拼装 —— 关卡侧 AI 手册

> 转向器 = 一个 90° 弯道滑梯网块 + 一个 `GSRedirectorComponent`。球**碰到正面圆弧接地那块**就自动被带着滑过弯道、滚上它连接的墙面/天花板，重力随之平滑转向。**不用写代码、不用建蓝图**。
> 本手册全部内容在 `测试案例` 关卡的四个转向器上 PIE 实测通过（2026-09-11，正向 4 例 + 反向 4 例 + 侧面撞击不触发）。
> 交接史与踩坑详见 `HANDOVER_zflip.md` §22-§24。

## 0. 先懂机制（30 秒）

- 重力权威是全局 `GSGravityManager`（六方向）。G 键是**手动**翻转；转向器是**关卡驱动的转向**：球碰到滑梯入口 → 重力沿弯道平滑旋转到出口面 → 球顺势滚上那个面。
- 组件按"**一对连接面**"建模：`GravityDirectionA/B` = 滑梯两端连接的两个面各自的重力方向。**双向可用**：球从任一面滚来都会滑到另一面——入口面由"球当前重力"自动识别。
- 90° 弯道下有一条天然规律：**入口行进方向 = 出口重力方向**。所以配置只需要知道"滑梯两端各贴哪个面"。

## 1. 摆什么（两种做法）

**做法 A（推荐，零建模）**：复用现成滑梯网格 `Content/_GENERATED/20625/Boolean_7E5C5321`（方块+圆柱布尔出的 90° 弯道，沿 X 挤出）。Place Actors 放一个 StaticMeshActor 或直接复制测试关卡里的 `转向器N` 再改位置。

**做法 B（自制滑梯）**：任何"90° 圆弧滑道"网格都行，但**必须满足两点**：
1. 沿滑道方向是**直的**（可沿该方向任意平移，多个转向器共用一个网格没问题）；
2. **网格资产必须有物理碰撞**——建模导出的网格默认没有，球会直接穿过去。检查/修复：
   - 静态网格编辑器 → Collision → Collision Complexity = **Use Complex Collision As Simple**（本项目 `Boolean_7E5C5321` 已这么配）；
   - 或加简化碰撞（盒/凸包）；
   - 验证法：PIE 里把球从滑梯正上方丢下去，球应停在滑梯面上而不是掉到地上。

## 2. 摆位规则（决定手感好不好）

- 滑梯要摆在**入口面与出口面相交的墙角**，"鼓包"朝房间内：球从入口面（地面/墙面/天花板）滚过来，必须能**先碰到圆弧最贴地的那一截**再顺势爬弯。
- 同一网格在不同墙角用**旋转**适配（参考测试关卡：地面↔墙两件互成 yaw 180 镜像，墙↔天花板两件 roll 180）。旋转只有 0/90/180/270 这些正交角度时数学才成立——别自由角度乱转。
- 滑梯沿**挤出方向（局部 X）平移无副作用**，可以贴着墙横着排一串。
- **转向器触发是"接触式"的**：只有球贴上"正面圆弧 + 靠近入口面"才触发。撞侧壁（沿挤出方向撞进来）、撞顶面/背面、从背面路过，都不触发、也不带走球——所以滑梯**凸出在通路里是设计特性**：横着走会撞上、只有正对圆弧滚进来才会被转向。

## 3. 挂组件并配置（唯一必配项：两个面）

选中滑梯 StaticMeshActor → 细节面板 **Add Component → GS Redirector**，然后配置：

**GravityDirectionA / GravityDirectionB** = 滑梯连接的两个面各自的重力方向（必须互相垂直）。常用对照：

| 场景 | A | B |
|---|---|---|
| 地面 ↔ 左/右墙 | NEGATIVE_Z（地面） | NEGATIVE_Y 或 POSITIVE_Y（墙在哪侧就朝哪侧） |
| 墙 ↔ 天花板 | 墙的重力方向 | POSITIVE_Z |
| 任意两垂直面 | 面上"下"的方向 | 另一面"下"的方向 |

判重力的口诀：**球站在这面上时，重力方向 = 从球指向这面的方向**（地面 −Z；y=2400 墙是 NEGATIVE_Y；y=3100 墙是 POSITIVE_Y；天花板 POSITIVE_Z）。

可调参数（默认值即测试关实测值，一般不用动）：

| 参数 | 默认 | 作用 |
|---|---|---|
| RideSpeedCm | 800 | 滑行速度（入口更快就按入口，上限 MaxRideSpeedCm=1200） |
| RidePathLengthCm | 260 | 滑过多少厘米完成重力旋转 ≈ 弯道弧长 |
| TriggerInflateCm | 120 | 触发盒外扩（廉价先筛；真正触发看下面三条门） |
| MinTriggerSpeedCm | 20 | 几乎停着的球不触发 |
| ContactTouchMarginCm | 20 | "碰到圆弧"容差（球面到滑梯表面距离 ≤ 球半径+此值） |
| EntryLipBandCm | 60 | "正面接地那块"判定带（球心离入口面 ≤ 球半径+此值） |
| MaxLateralNormalDot | 0.7 | 接触面法线偏出弯道轴超过它 = 撞侧壁，不触发 |
| EntryAlignmentMin | 0.35 | 速度必须大体朝出口方向 |
| SlowEntrySpeedCm | 100 | 速度低于它的球豁免方向判定（被滑梯顶停也能触发） |
| CooldownSeconds | 0.3 | 触发冷却 |

**触发语义（背下来，排查手感问题全靠它）**：触发 = 球贴住滑梯 ∧ 接触面不是侧壁 ∧ 球心在"入口面附近" ∧ (速度朝出口 或 几乎停住)。不触发 = 撞侧面/顶面/背面、或从背面路过、或完全静止。

## 4. PIE 自验配方（两面 + 侧面，三分钟）

1. 组件细节面板勾 **bDebugLog**；PIE。
2. 正向：球放在滑梯入口面外 ~250cm，朝圆弧滚过去 → 日志应出现 `fired ... A→B`，球滑上出口面，`GSGravityManager.CurrentDirection` 变成出口面。
3. 反向：把球放到出口面上，朝滑梯滚回来 → 同样触发，方向互换。
4. 侧面：球沿**滑梯宽度方向**（挤出方向）滚过来撞侧壁 → **不该触发**，日志应有 `gate[side]`。
5. 没触发就看门限日志：`gate[touch|side|lip|speed|align]` + 球位/速度/align/touch，哪道门拒的一眼可见；Pawn 上 `bRedirectDebugLog` 还有逐帧滑行数据（`[GSRedirect]`）。
6. 测完把 bDebugLog 关掉（组件级日志会刷屏）。

## 5. 踩过的坑（每条都真实发生过）

1. **网格没碰撞** → 球直接穿过滑梯（先做"正上方丢球"验证，见 §1.2）。
2. **自由角度乱转** → 弯道轴不再与网格挤出方向一致，侧壁/接地判定全部失准。只用正交旋转。
3. **把滑梯摆在离墙/地有一段距离的地方** → 球碰不到"圆弧接地那块"，永远不触发。滑梯必须与两面**齐平相接**。
4. **组件参数改了忘存盘** → 组件实例数据随关卡(umap)保存，改完记得 Ctrl+S。
5. **同一网格资产改碰撞设置会影响所有实例**（好事：一次改全生效；坏事：别忘了别处也在用）。
6. 验证脚本注意：PIE 期间要用 `UnrealEditorSubsystem.get_game_world()`（不是 get_editor_world）；给球注入速度会被"松键刹车"在恢复帧吃掉——测运动用关卡里现成的持续驱动方式（见 HANDOVER §23 的测试方法坑）。

## 6. 2026-09-13 新增:两道"真实性"门 + 单面进入开关

- **背景**:球**悬空**从墙沿掉落、擦到滑梯边缘也会触发(用户反馈"没上圆弧也触发、卡得莫名")。
- **支撑门** `bRequireSupportToTrigger`(默认开):触发瞬间球必须在支撑态、悬空 ≤ `MaxAirborneSecondsForTrigger`(0.2s)。滑地/滑墙进入照常,空中飞过不算。
- **分离门** `bRejectSeparatingContact`(默认开):速度沿接触法线朝"离开滑梯"方向 > `SeparationRejectSpeedCm`(150) 拒绝。
- **单面进入开关** `bAllowEntryFromA/bAllowEntryFromB`(默认都开=双向):只想让球从地面滚入 → 关掉墙那面。
- 验证:地面滚入应照常触发;空中擦过日志应有 `gate[airborne]`;被拒时 `gate[...]` 会打印实测值(先开组件 `bDebugLog`)。
