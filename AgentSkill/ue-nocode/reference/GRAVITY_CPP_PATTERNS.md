## 两个必查 bug 模式(2026-09-02 实修)

0. **滚球力矩轴反了 = 操作镜像(W 后退、A 向右)**:让球滚向 `Desired` 的力矩轴是 **`Up × Desired`**,不是 `Desired × Up`——接触点运动学 `v_center = -wr·(Up×T)`,写反后球滚向反方向且左右镜像。配套:**松键制动**靠反向力矩(无输入且支撑时 `T = Up×(-v̂)`),物理滚球只靠摩擦会滑很远。
1. **弹簧臂滤掉翻转旋转**:`CameraPivot` 每 tick `SetWorldLocationAndRotation` 写绝对旋转,但中间 `SpringArmComponent` 若 `bInheritPitch=false`(模板常见写法),180° 翻转(本质是 pitch)传到相机前就被臂吃掉。表象:摄像机永不跟转,`CAM_UP` 恒等 (0,0,1)。
   修:`CameraPivot->SetUsingAbsoluteRotation(true)`(隔绝球体滚动渗入)+ 臂 `bInheritPitch/Yaw/Roll = true`。
2. **睡眠刚体无视 AddForce**:重力组件每 tick `AddForce(bAccelChange=true)`,但刚体落定睡眠后力全部无效。表象:翻转 ACCEPTED、`GetGravityDirection()` 变了,球/方块纹丝不动。
   修:`UGSGravityBodyComponent` 订阅 `OnGravityChanged`(`BeginPlay` AddUniqueDynamic / `EndPlay` Remove),handler 里 `TargetPrimitive->WakeRigidBody()`。
3. **关卡摆放 Actor 的 BeginPlay 早于 GameMode 自动 spawn 的 Manager**(时序家族第三例,v2 的 EnableInput 丢失是第一例):BeginPlay 时 `FindGravityManager` 返回空 → 注册/订阅全跳过且**无重试** → 该 Actor 永远不响应翻转(`GetGravityDirection()` 空管理器时恒返回 -Z)。**验证信号:`get_registered_body_count()` 只有球一个 = 关卡 Actor 全没注册**。
   修:**懒绑定**——注册+订阅挪进 `RefreshReferences`(两者都幂等),`TickComponent` 里 manager 为空就重试。
4. **不滚转的相机下,移动基向量别用 `Up×Forward`**(2026-09-03):轨相机 roll 锁世界竖直,重力翻转(Up 反向)会让 `Up×Forward` 右向量反向而画面不翻 → **天花板/墙面 A/D 镜像**(用户实测)。修:移动基向量直接取**相机自身 forward/right 投影到支撑面**(相机 right 恒等于屏幕右,任何姿态都对);滚转跟随型相机两种算法等价,不受影响。配套:验证时读"相机朝向"要用 **CameraComponent** 的 right,`get_component_by_class(SceneComponent)` 拿到的是根碰撞体(物理翻滚中),读出来全是误导。
   **评审"自定义重力+翻转"类代码先查这几处。**

## UHT/编译期撞名(2026-09-03)

- **组件新 UFUNCTION 撞基类名**:给 `UActorComponent` 子类加 `IsActive()` 的 UFUNCTION → UHT 报 "Override of UFUNCTION 'IsActive' in parent 'UActorComponent' cannot have a UFUNCTION()"。`UActorComponent` 已占用 `IsActive`;新组件方法避开 `Is*/Get*` 常用名,或先查基类(本次改名 `IsDriving`)。

## 平滑相机的"写后漂移"坑(2026-09-08 相机抖动轮,PIE 逐帧数据实证)

**症状**:相机移动"卡卡的"+瞬间小幅抖动;多张图同发 = 查共用的相机链,别怀疑关卡。

**根因模式(泛用,记牢)**:平滑组件的父级是**物理模拟的根**(翻滚球体等),且只把**旋转**设绝对(`SetUsingAbsoluteRotation`)、**位置仍是相对**——每帧 Tick 里 `SetWorldLocationAndRotation` 写完平滑位姿后,同帧物理步里父级一动,子组件继承父级当帧位移 → **这段未平滑位移绕过全部平滑层直进画面**。匀速=拖拽感,加速/急刹/碰撞帧=瞬间抖动。本质:"写时平滑、写后漂移"。

**修复模式**:枢轴位置同样绝对化——`SetUsingAbsoluteLocation(true)`(BeginPlay 应用,配 `bUseAbsoluteCameraLocation` UPROPERTY 默认开,留 A/B 口)。修复后逐帧实测漂移 0.00cm。

**逐帧数据采集法(关键,python 采样不出来)**:远程 python 执行期间世界暂停,组播采样只能拿到粗粒度。正确姿势=C++ 里加 UPROPERTY 门控的逐帧 `UE_LOG`(默认关),PIE 里开、跑完读 `Saved/Logs/<项目>.log` 用 python 解析。**打点读"写入前"的组件位置**(pivotPrev):它 - 上帧写入值 = 每帧泄漏量,旧行为=球位移,修复后=0。日志开关设在**PIE 实例**上立即生效(别走 CDO,见 PYTHON_API_PITFALLS)。

**A/B 复现法**:开关做成 UPROPERTY 且 BeginPlay 逐实例应用 → 细节面板切换即可对比新旧行为,免重编。

## 滚球 WASD 手感:力矩驱动会打滑,平面加速度才是正解(2026-09-08 实测定案)

- **症状**:力矩驱动(AddTorqueInRadians)的滚球移动"过慢+惯性大",调力矩档位终端速度几乎不动。实测真相:球在低摩擦接触下大量**打滑**(自转 ω·r≈3000 cm/s 而 |v|≈240)——力矩把球转起来了,接触摩擦没把转动转化成位移。
- **修复模式**:支撑面上的 WASD 驱动改用**平面加速度** `AddForce(Desired·DriveAccel, NAME_None, true)`(bAccelChange=质量无关加速度),绕开牵引耦合;松键刹车用**平面速度直接衰减** `Planar *= Exp(-ReleaseBrakeHz·dt)`(~3Hz≈1s 停稳),竖直分量原样保留。
- **经验公式(实测三组线性吻合)**:终端速度 ≈ DriveAccelerationCm×0.28(综合减速约 3.5/s,比重力体 Profile 的切向拖拽 0.35 大 10 倍,原因未深究——手感调参以实测为准)。目标终端 → 除以 0.28 得驱动力。
- ⚠ 标定必须在干净平地(无斜坡/结构/表面体积/薄地板);校准板要厚(≥5m)防高速穿透;位置+速度联合采样,单看速度全是地形噪声。切向拖拽是重力侧参数(影响掉落),别拿它调移动手感。

- **`FMath::VInterpNormalRotationTo(Current, Target, dt, Speed)` 的 Speed 单位是度/秒**:转 180° 要 180/Speed 秒——想要 ~0.5s 完成的方向摆动得传 360-400(2026-09-08 传 8 实测摆了 22 秒没到位)。同理注意 dll mtime:编辑器运行时 UBT 报 Succeeded 但可能没真正链接,重编前必关编辑器、编完必对 dll mtime

## 弹簧臂探针在棱边逐帧翻转 = 画面抖动;自建探针 + 去弹(2026-09-09 爬楼梯轮,逐帧日志实证)

**症状**:爬楼梯(Z 重力态)时画面抖动;平地上正常。

**根因模式(泛用)**:`USpringArmComponent` 自带碰撞探针在**台阶/平台棱边**处会**逐帧翻转**——本帧命中(臂长被压到 179)、下帧失配(回到 700)。相机位置 = 枢轴 + 臂向 × 实测臂长,于是相机每帧前后抽 ±500cm、俯仰 ±6.4°。**任何一阶滤波都压不住这种方波**(试过 `bEnableCameraLag`,周期≈帧长时只削幅值几乎无效)。

**修复模式**——关掉自带探针(`bDoCollisionTest=false`),自建探针 + 去弹:
1. 每帧沿"枢轴→期望相机位"打一条 `ECC_Camera` 线探针(`LineTraceSingleByChannel`,忽略自身);
2. 命中 → 立即收短(`FInterpTo` 8/s,防穿墙);**连续无命中 ≥ `ArmExtendHoldSeconds`(0.7s)才缓慢放长**(5/s)——翻转被去弹,相机稳定在安全距离,离开棱边后平滑拉远;
3. `TargetArmLength = 平滑臂长` 每帧写回;**抬升缩放(LiftScale)与瞄准高度 AimUp 必须同乘**、`CamPosApprox` 也用平滑臂长——否则臂一收短,枢轴抬升缩了而瞄准点没缩,俯仰会甩 13°、构图跳变。

**实测**:修复前楼梯段相机 X 每帧 ±500cm、俯仰摆到 +14.6°;修复后每帧平滑 +15~22cm、俯仰 −1°±3°。

**逐帧诊断法**:加 `bFallbackCamDebugLog` 门控日志(球位/枢轴/平滑前后目标/相机位/臂长/命中体/缩放/俯仰),再配一个 `bDebugAutoDriveForward` 调试开关持续前推(替代 OS 按键注入),脚本把球放到楼梯口即可自动爬完,读 `Saved/Logs/*.log` 解析。**后台节流下 python 采样只有 ~3 帧/秒,必须靠 C++ 逐帧日志。**

## 瞄准目标里不能用"瞬间换边"的源(2026-09-09 按 G 突变轮)

**症状**:按 G 翻转时画面"突然向上/下跳一下";位置通道已平滑但仍有突变。

**根因模式**:瞄准点用 `SupportUp`(=−重力)构造——G 按下瞬间它**瞬间反向**,瞄准点瞬移 ~284cm,俯仰一帧跳 ~22°,之后又随枢轴慢慢飘回。**判据:任何进入相机姿态计算的量,只要其源会瞬间换边,就会造成瞬时跳变。**

**修复**:瞄准点/判别项改用**已平滑的抬升方向** `CameraLiftDirection`(收敛后与 SupportUp 等价,过程中连续)。**验证相机"突变"必须同时采位置和旋转**——只采位置会漏掉俯仰跳变(本项目第一轮就是这么漏的)。

## 旋转重力式"转向器"(滑梯换面)实现模式(2026-09-11 转向器轮,PIE 正反 8 例全过)

**需求**:球碰滑梯 → 自动滑到它连接的墙面上、重力随之连续旋转(替代 G 键直接换向),**且双向生效**。

**六条定式(都是先踩坑后定的)**:
1. **双向:按"一对连接面"建模,不要按"出口方向"建模**。只给出口方向的设备天然只能单向(用户第二版反馈的原话:"你这个只有单项生效")。正确姿势:`GravityDirectionA/B`(两面必须垂直)= 转向器连接的两个面,**入口面由球当前重力识别**(与哪面更接近就是哪面),出口取另一面。90° 弯道下"入口行进方向恒等于出口重力方向",于是**进入判定(速度·出口方向≥min)一条规则覆盖正反双向**;先判"球是否在某个面上"(dot≥0.5)再判方向,背面/天花板路过不会误触发。`cross(入口上,出口上)` 得到的弯道轴在反向时自动反向,整套滑行/旋转机制不用改。
2. **重力按"滑行距离"旋转,不要按时间**:`PathCm += |v_actual|·dt; Alpha = PathCm/PathLength`——球被挡住/变慢时重力先不转;按时间会出现"球还在坡上、重力已转完",球被压死在半坡(实测:0.8s 转完 vs 球要 7s 才出坡)。
3. **滑行速度锁在"弯道当前切向"**:`forward = cross(当前上, 弯道轴)`,每帧 `SetPhysicsLinearVelocity(forward*RideSpeed)` 而非 AddForce——摩擦/坡面阻力全绕过,球快转快、球慢转慢。
4. **球面探针贴面(不然布尔网格会把球弹飞)**:每帧从球心沿 -Up 打 `Radius+120cm` 线,命中则 `指令速度 = VectorPlaneProject(forward*Speed, 命中法线) + 命中法线 × clamp(-空隙×6, ±Speed)`——指令速度永远切于**实际**接触面并按空隙吸回面上;理想弧线只作方向参考(实测:不做投影时碰撞解算吃掉 92% 位移)。
5. **状态机与会话**:Pawn 上 `bGravityRedirectActive` + `From/To/Current/Axis/Speed/PathCm`;`GetActiveGravityDirection()` 在过渡期返回**旋转中的中间方向** → 相机抬升、驱动平面、物理重力(经 GravityBody 的 `GravityDirectionOverride`)读同一个源,全程连续;**旋转走完才提交管理器**(提交瞬间两者一致,零跳变);滑行期间抑制 WASD/刹车/G/1-2-3,落地响应与自动反转直接 return(防半路弹跳/反转把球扯下来);释放由触发它的组件负责(球离开触发盒),另设 5s 超时保险。
6. 网格侧:建模工具布尔网格**没有简单碰撞体**,把资产 collision_trace_flag 改 `CTF_USE_COMPLEX_AS_SIMPLE` 球才真的被滑梯接住(多实例共用资产 → 一次改全生效)。

**逐帧诊断**:Pawn 加 `bRedirectDebugLog`(球位/实际速度/指令速度/接触体/空隙/重力上/进度),组件加 `bDebugLog`(armed/fired/released,含 A→B)→ 比盲调参数快一个数量级。

**测试运动状态的坑**:见 PIE_TESTING.md"注入速度活不过暂停帧"(自动驱动方向不同向时会把速度方向盖掉)与"相机航向是实例级残留状态"(绝对角度重设法)。

## 转向器触发与释放的两条补充定式(2026-09-11 第十五轮,PIE 实测)

**补 1:触发必须由"真碰到圆弧"决定,不能只看触发盒**
- 触发盒外扩只是**廉价先筛**;真正的门是"球面到滑梯表面距离 ≤ 半径+容差(默认 20cm)"。只按盒触发 → 球在半空就被旋转重力,手感诡异(用户反馈)。
- 距离怎么测(踩过一轮):
  - **球面扫掠(SweepSingleByChannel)不行**:球静止在地面上时扫掠起点已与地面重叠,扫掠立刻返回地面、永远打不到滑梯(所有触发全失效)。
  - `GetClosestPointOnCollision` 对"复杂碰撞当简单用"的网格**返回 -1**(文档要求 simple collision)。
  - **可行解:多方向线探针**——从球心沿 {朝网格包围盒最近点, 入口"下", 出口"下"} 打线,命中自身网格且距离 ≤ 半径+容差 → 碰到。线从球心出发不与地面重叠 ✓,实测正向进入正好在"球碰到坡面那一帧"触发。
- **贴住滑梯时要放宽速度/方向门**:反向(从墙上/天花板上下来)时球常被滑梯几何**顶停在坡面**(速度掉到几十),若仍要求"速度≥50 且方向 align≥0.35"就会被拒 → 表现为"逆不回去"。规则改成:接触为真 → 速度门不生效、方向门放宽到 -0.5(不是明显往外走就带走);没接触 → 按原门限。

**补 2:释放条件 = 离开触发盒 **且** 重力旋转已走完**
- 只按"离开盒"释放,会在球还没滑完弯道时留下一个"介于两个面之间"的重力,看着像"没转过去"。Pawn 暴露 `GetGravityRedirectProgress()`,组件在 `离开盒 && progress>=1` 才释放(另有 5s 超时保险)。

**调试法(一次到位)**:组件 `bDebugLog` 打开后,球在触发盒内**每帧**打 `gate[speed|face|align|touch]` + 球位/速度/align/touch;再加每 30 帧心跳 `tick ball=... inBox=... riding=...` 确认 tick 在跑。定位"为什么不触发"不再靠猜。

**测试运动状态的三个坑(本轮新增)**
- **导轨相机让 move_input 方向不可靠**:本关(测试案例)走导轨相机,驱动方向由导轨决定且**随球沿导轨的位置变化**——同一 move_input 在不同位置驱动方向不同。测运动改用"**注入世界速度 + 极小驱动力(50)只为关掉松键刹车**",并在多次脚本调用间**反复重设速度**(每次调用世界推进 ~0.4s)模拟持续驱动。
- **用例串场**:上一个滑行没释放就摆下一个用例,新设的重力会被旧 `GravityRedirectCurrent` 覆盖 → 用例间留足时间或重启 PIE。
- **测试坐标按 actor 实际位置推导**:关卡里的转向器可能被拖动(本轮就遇到 1/3 号沿 X 挪了 250~300);滑梯沿挤出方向平移是无害的,但写死坐标的用例会打空。

**补 3:撞侧面不触发——看"接触面法线",不要看速度**
- 需求:只有"正面圆弧接地那一块"才触发;撞滑梯侧壁(平直面)一律不动(用户反馈:撞侧面还是会动)。
- **只看速度方向不够**:球撞侧面后**弹开**,速度转一下 align 就变正,又被放行触发(实测:先按速度拒了两次,弹开后 align≈0 却触发)。
- **正解**:接触时取回**接触面法线**,`|dot(法线, 弯道轴)| > 0.7` → 撞的是侧壁(法线沿滑梯宽度方向=弯道轴)→ 不触发。球只要还贴着侧壁就永远不触发,与瞬时速度无关。
- 另加"**正面接地那块**"位置门:球心到**入口侧面**(地面/墙/天花板那一侧的面,= 网格包围盒在入口重力方向上的支撑面)的距离 ≤ 球半径 + 60cm。⚠ **符号坑**:`Center - Sign(N)*Extent` 会取到**对面**(顶面),所有正常触发会被拒;正确是 `Center + Sign(N)*Extent`。
- 方向门保留但加**低速豁免**:`align ≥ 0.35`,速度 < 100cm/s 时豁免(反向下滑常被顶停在坡面,方向已无意义)。
- 触发判定顺序:接触 → 侧壁(法线)→ 接地(位置)→ 最小速度 → 方向。调试时逐门打 `gate[touch|side|lip|speed|align]` 一目了然。

## 相机/转向器/方块/楼梯四修(2026-09-13 第二关测试轮,全部 PIE 实证)

- **相机探针必须沿"相机真实最终朝向"打**:相机姿态里有瞄准俯仰微调(AimPitchDeg,最多 ~17°),旧探针用未含微调的平滑旋转 → 贴墙时探针判"安全"而相机已进墙。"容易穿模"主因之一。探针线改**球扫掠**(半径 ~18)更抗斜擦;命中侧**瞬时压入**(平滑收短期间相机停在墙里就是穿模)。
- **"瞬时压入"别写成 Min(当前, SafeArm)**:障碍变远(SafeArm 未满但大于当前臂)时臂长被永久钳住涨不回去——死锁。正确:障碍比当前臂更近才瞬时压入,否则按"驻留+限速"放长到 SafeArm。
- **近距球遮挡**:臂长塌到极短时隐藏球网格(滞回 230/300,瞄准中不隐),纯视觉零物理影响。
- **操作基向量随相机角度自适应**(用户定则):FaceOn=|视线·支撑上|;平行(平视)=旧行为,正对→屏幕相对(W=屏幕上方向的面内投影——正对墙面时就是"向上爬")。区间混合;**正对墙(墙上跟随常态)时视线水平分量≈0,必须由屏幕相对端兜底**。
- **转向器"没上圆弧也触发"**:旧门(接触/侧壁/接地/速度/方向)拦不住"悬空擦过"——球从墙沿掉落、速度含离面分量(v·n>0)且方向恰好沿出口就 fire。加固:①支撑门(IsSupported + 悬空 ≤0.2s)②分离门(v·n > 150 拒绝)③单面进入开关(A/B 各一,默认双向)。验证:地面滚入照常 fire,空中擦过打印 `gate[airborne]` 拒绝。**贴墙下滑被接住 = 双向设计,不是 bug**(不想要就关单面)。
- **`bImmovableByPlayer` 是"推不动"的总开关**:只配 `ImmovableMassKg=2000` 不开开关 ≠ 不生效(队友踩过:球照样推得动)。关卡改了属性记得 `save_current_level()` 并让另一头拉 umap。
- **楼梯吸力(防爬楼飞出去)**:沿重力向下探针,命中 actor 名字/类名含 "Stairs" 才施加朝支撑面加速度(默认 1500,探针 = 半径+150);球被台阶弹起的瞬间探针仍探到台阶、拉回来。其余表面零影响。


## 特殊滑梯"面吸附"(竖直面 → 平面,2026-09-15 实测通过)

**适用**:一段连接"竖直面(垂直于地面)"与"平面(平行地面)"的**凸圆弧**滑梯(如 BlockoutTools `SM_Blockout_Curved_Corner_Outer_Q1`)。
**与 90° 弯道滑行的分工**:弯道滑行要求球已骑在某一面上沿弧滚出;**面吸附**接的是"球从侧面碰到竖直面"那一下——那一下在旧逻辑里正好被"撞侧面不触发"(法线×弯道轴)拒掉。

**算法骨架**(方向推导不依赖网格朝向,只靠两面法线):
1. 入口面法线 `N_in`(碰到的那面)、出口重力 `G_out` → 出口面法线 `N_out = -G_out`;
2. **旋转轴** `Axis = normalize(cross(N_in, N_out))`;两面平行 → 放弃(构不成弯);
3. 每帧:从球心沿 **-当前接触法线** 打探针取回**真实曲面法线** N(凸弧上门控/理想弧线都会骗你,只有真实法线能带球走完);
4. **切向** `T = normalize(cross(Axis, N))` —— 入口时朝"上",出口时朝"外",方向随 N 连续旋转 = 自然被带到平面;
5. 速度 = `T * DriveSpeed + N * clamp(-gap * GapGain, ±Speed)`(法向合拢),另加 `-N * StickAccel` 的加速度压住凸面甩开趋势;
6. 重力按**走过的路程** slerp(N_in→N_out 的对应重力),**不是按时间**;
7. 出口判定:`dot(N, N_out) >= ExitNormalDot(0.85)` → 提交重力并释放(带切向速度滚上平面);另有超时保险。

**踩过的坑(都要写进代码注释)**:
- **必须关掉"吸附 + 旧弯道逻辑"并存**:吸附把球送到平面的**同一帧**,球正好贴着圆弧、重力已转成平面重力,旧逻辑立刻判定"从平面进入"又来一次反向滑行,把球原路甩回去。→ 加 `bFaceCaptureAlsoClassic`(默认 false)。
- **"碰到就吸附" vs "停着别吸"**:球在竖直面上被松手刹车停住时速度只有 8~14cm/s,`MinTriggerSpeedCm`(20)正好把它挡住 → 这是"停着的球不该被吸走"的正确行为,别当 bug 修。
- **探针要能命中滑梯本体**:球贴在滑梯**下方**（圆弧还没开始的那段墙)时,朝面法线反向的探针打到的是**别的网格**(关卡墙),`HitActor != 滑梯` → 不触发;只有球中心越过圆弧起点后才命中本体。参数化测试时把球放到"贴弧接触点"能快速验证机制,真实触发要靠输入驱动爬上来。
- **注入动量不可靠**:松手刹车按 `Exp(-ReleaseBrakeHz*dt)` 吃掉线速度(实测 900→42/秒),测"攀爬触发"要用 `enable_native_polling_input=False` + `set_move_input` 驱动,别指望 `SetPhysicsLinearVelocity` 一脚。

## 相机"收尾复核扫掠"(治残余穿模)

**现象**:探针算出来的臂长"看起来安全",相机偶尔还是进墙(个别帧)。
**根因**:探针用的是**上一帧**的俯仰/枢轴位置,与**本帧最终相机位**差一个夹角+一段位移;另外部分关卡网格**只挡 Visibility 通道、不挡 Camera 通道**,单通道探针会漏。
**修法**:在写完最终枢轴位置与最终朝向之后,再扫一次——起点=本帧最终枢轴、方向=最终朝向、长度=当前平滑臂长,**两个通道(`ECC_Camera` + `ECC_Visibility`)都扫**,命中即立刻压短并清零"无命中驻留计时"。只收紧不放松 → 开阔场景观感不变。

## 贴脸遮挡:判"屏幕占比"而不是臂长

**现象**:球已经糊住半屏,"贴脸隐藏/半透明"却不触发。
**根因**:触发条件只看臂长(`arm < 230cm`),但球的视觉占比取决于 **asin(球半径 / 相机到球距离)**——球大/视场窄时臂还很长就已经挡视野。
**修法**:用角半径判定 + 滞回(`FadeStartAngleDeg` 13° / `FadeEndAngleDeg` 9°),与臂长阈值取"或";瞄准态不处理。
**顺带**:判定"半透明不生效"时先查材质本身(`blend_mode == BLEND_TRANSLUCENT` 且 `Opacity` 标量参数已连到不透明度),再查触发条件——材质没配好时,换 MID 上去也是不透明。


## 瞄准(ADS)相机的两个隐蔽坑(2026-09-15 实测)

1. **越肩偏移不进探针 = 瞄准态穿模**:ADS 常用 `SpringArm->SocketOffset.Y = 65cm` 让位,相机实际位置**横向偏出臂轴线**;所有"沿臂轴扫掠"的防穿墙探针都扫不到这 65cm → 只要侧向贴墙就穿模。**修法**:复核扫掠的终点改成"**枢轴 + SocketOffset(世界) + 臂长方向**"这个真实相机位,沿"枢轴→相机位"扫;命中比相机位近就按超出量收臂(偏移是固定量,只收臂),逐帧收敛。
2. **FOV 收窄会放大"占屏比例"**:ADS 把 FOV 从 90 收到 55,球角半径不变但屏幕上大一截。任何"球占屏太大就淡出/隐藏"的判定,**阈值必须随 FOV 缩放**(`scale = clamp(FOV/90, 0.45, 1.4)`),否则"瞄准时球糊住半屏"永远不触发。同理,原来写死"瞄准态不处理"的逻辑要留开关(用户可能就是要它处理)。

## 让球"贴面"的力要分上/下坡(楼梯吸力 2026-09-15 用户反馈)

沿重力方向压向支撑面的"吸附力"(防弹飞/防脱面)如果**无条件全强度**,在斜坡/楼梯上会把**上坡**拖难(用户原话:"吸力让上坡变困难")。**修法**:按球速沿重力方向的分量插值强度——下坡/停着 ≈1.0,上坡压到 `UphillScale`(0.2 起调)。判据只需 `dot(velocity_dir, gravity_dir)`,不用知道坡面法线。


## 贴面力的"端点延续"(楼梯端点防飞出去 2026-09-15)

**现象**:沿重力探针给"吸附力"(防弹飞)时,**球一离开目标件就断力**;偏偏端点那一下(最后一级台阶把球顶出去 / 坡口)才是飞出去的时刻。
**修法(通用)**:记录**最后一次确实命中目标件**的位置与时刻;离开后若仍在 `距离 ≤ Margin` 且 `时间 ≤ Seconds` 内,继续给一个**固定小力**(不乘坡度/方向系数——飞出去恰恰发生在最不利的方向上)。走远/超时立即清记忆,保证力量不会漏到别的表面。
**本机取值**:楼梯 `Margin=160cm / Seconds=0.5s / 力=600cm/s²`(主吸附 1500)。
**验证方式**:驱动球沿件走完一整程,采样轨迹——**垂直速度无尖峰、z 单调**即为"没飞出去"的趋势证据(体感仍需真人)。


## ADS(瞄准)越肩偏移:必须**单独钳**,收臂收不掉它(2026-09-15 实测)

**坑升级**:上一版做法是"沿'枢轴→含偏移的相机位'扫,命中就按超出量收臂" —— **方向性错误**。越肩偏移(`SpringArm->SocketOffset`)是**横向**位移:把臂长压到最短(40cm),相机依然横在侧向 65cm 处,墙里的相机永远出不来。
**正确做法**:两段分开钳——①沿臂轴扫 → 收臂长;②从"轴上的相机位"**沿偏移方向**扫 → 命中就把 `SocketOffset` 按比例缩小(直接写回组件,与臂长同"谁最后写谁生效")。
**实测对照**:未钳 65cm → 相机插进网格(z 命中距离 151 < 相机距离 155);钳到 9cm → 完全干净。

## 验收瞄准态:PIE 收不到注入的鼠标事件,用"强制瞄准"开关

- UE 用 **raw input** 收鼠标,`mouse_event`/`SendInput`(以及 CUA 的右击)**都不会产生 WM_INPUT** → 注入的右键进不了游戏(键盘注入正常,因为走 WM_KEYDOWN)。想复现"按住右键"的行为,别在注入上耗时间。
- 解法:C++ 里加一个 `bForceAimingDebug`(默认 false)—— `bAimDown = PC->IsInputKeyDown(AimKey) || bForceAimingDebug`。脚本 `set_editor_property` 打开即可**纯 Python 验收**瞄准态(FOV/偏移/臂长/材质/自打射线查穿模),不需要前台窗口、不抢用户焦点。
- **配套坑**:`enable_native_polling_input=False`(注入移动输入时常用)会**连 UpdateAiming 一起跳过** → 设了强制瞄准开关却看不到 fov 变化时,先把它设回 True。


## "防飞出去"治的是**速度**,不是力(楼梯下坡飞出去 2026-09-15,三轮才定位)

**典型误判**:用户说"还是会飞",第一反应是加大朝支撑面的**力**(1500→2400→3200)。**没用**——球被台阶棱角/端头顶起时已经带着离面速度,力要等它把速度抵消掉,而球早飞了。
**正确修法(两道硬约束)**:
1. **贴面时**:削掉速度里"朝离开支撑面方向"的法向分量(`V -= N * max(0, dot(V,N))`)——沿面滚可以、被棱角顶飞不行;
2. **空中时**(探针仍探到目标件):把"逆重力(上抛)"分量当场归零(`V -= Up * max(0, dot(V,Up))`)。
两者都只作用在"探针命中目标件"的判定区里,其它表面零影响。开/关对照:开=0 离地帧,关=连续 7 帧(2.3s)整段腾空。

**方法论教训(同一轮踩了两次)**:
- 这类"飞/弹/抖"是**亚秒级**事件:**0.5s 级 Python 采样会得出"没有飞"的错误结论**(本轮前两次 A/B 就是这么被骗的)。必须加**逐帧门控 UE_LOG**(默认关的 `bXxxDebugLog`),跑完解析 `Saved/Logs/<项目>.log` 对照。
- 采样型验收(《PIE_TESTING》"fire→等→read")只适合**状态量**(重力方向/是否吸附/材质),**逐帧行为量**(离地帧数、抖动、弹跳)必须走日志。


## 楼梯"下坡飞出去"的完整结论(2026-09-15,四轮才收敛)

1. **力治不了**:加大朝支撑面的力没用(1500→3200 都试过)。台阶**不连续**,球速一快就在每级边缘起跳,力只能让抛物线落得更快、落点还是被跳过的那些台阶。
2. **削"上抛分量"也不够**:实测飞行时 `vz` 一直是**负的**(是"落得更快的跳跃",不是"朝上飞"),削上抛削不到。
3. **正解是限速**:把水平速度钳住(如 700cm/s),单位时间跨越的台阶少、每级下坠量(≈1cm)远小于台阶高(30cm),球就贴着台阶滚。实测同一段:只削速度 9/16 帧离地 → 加限速 **0/15 帧离地**。
4. **削速度必须按"趋势"门控,不能按瞬时方向**:爬台阶需要向上的速度,被顶飞也是向上的速度——瞬时方向区分不了。用**垂直速度的指数均值**(≈0.17s)判"在上坡还是下坡",上坡时把削速度/限速全部关掉,否则"其他楼梯都上不去了"(实测踩过)。
5. **用户说"只改那一段"时就真的做作用域**:加一个逗号分隔的名字清单参数(target actor 名字/类名匹配),命中才用强化值/硬约束,其余走基础值 —— 比全局参数安全得多。


## 第三人称相机:偏航"拖不动 / 只能往一边"的两个耦合真因(2026-09-15 实机定位,附验收法)

**症状**:玩家说"在狭窄处想对某个方向转相机,怎么拖都转不过去""往右拽没用、只能往左"。

**真因① 偏航绕错了轴(决定"转不动")**
`BuildCameraRotation(Up, AdditionalPitch)` **内部总是**把 `CameraPitchDegrees` 计进
`TotalPitch = Clamp(CameraPitchDegrees + AdditionalPitch, ±Max)` —— 所以任何从它派生的"当前相机上轴"
(如 `CurrentCameraUp = CurrentCameraRotation.RotateVector(Up)`)其实是**带俯仰的倾斜轴**。
绕倾斜轴转航向,水平方位只变化 `cos(俯仰)` 倍(俯仰 70° → 只剩 0.34 倍,实测 0.23)→ 玩家感受就是"转不动"。
**修**:航向必须绕**不含俯仰的支撑上轴**(`TargetCameraUp = -gravity`,未翻转时=世界 up)旋转。

**真因② 航向的竖直漂移(决定"方向不对称 / 时灵时不灵")**
航向被绕"过渡中 / 带俯仰的轴"反复旋转会累积竖直分量,最终与上轴近乎平行 → 投影到 ⊥上轴平面后长度趋零、
方向极不稳定 → **不同拖拽方向表现不同**(恰好解释"右边没用、左边能用")。
**修**:**每帧**把"去掉竖直分量"的航向存回 `CameraAimHeading`(投影是幂等操作)。

**验收法(可复用)**:
1. 用 `pivot→cam` 的水平方向**反推航向方位角**(绕开俯仰干扰);发一次 `add_camera_look_input(+90,0)`,
   看方位角是否**正好变化 90°** —— 1:1 才算对;偏小就是真因①;
2. 对称测试 `+45 / −90`,响应不对称就是真因②(航向近竖直)。两 bug 会叠加:先修①再修②。

## 挤窄处的相机:别让"瞄准俯仰"把视线永远压向地面

第三人称常靠"枢轴抬升 + 看向球"把球压到画面下三分。**臂被墙挤短时**这条偏置仍把相机往下压
(实测低头中位 51°、顶到 70° 限位):玩家想平视就得**全程顶着鼠标**,一松手被拉回低头 → 主观就是"转不过去"。
**修**:按"挤窄程度(1 − 臂长/满臂)"衰减这段瞄准俯仰(最挤保留 30%),满臂不衰减、开阔处构图不变。

## 相机探针的两个"过度保守"陷阱(会把臂长钉死 → 相机贴脸 → 更像"转不动")

1. 球扫掠半径别开大(18cm 太大):**只是从相机侧边擦过、根本不在视野里**的墙也会立刻命中 → 臂长被钉在最短。
2. 探针别扫 `ECC_Visibility`:击杀体/触发体这类"只挡 Visibility 不挡 Camera"的游戏体会被当成障碍。
   → **只扫 `ECC_Camera`,半径 ≈9、余量 ≈6。**

## 鼠标视角"完全没反应"但键盘正常 = 鼠标捕获丢了(不是相机 bug)

引擎源码 `EngineBaseTypes.h`:`CapturePermanently` 与 `CapturePermanently_IncludingInitialMouseDown`
**都要求"先点击游戏视口"才捕获**,区别只是那次点击要不要也送给玩家输入。捕获丢失
(Alt+Tab / Esc / 打开菜单或设置界面 / 点编辑器面板)后**必须再点一次视口**。键盘不受影响
→ 典型签名是"**WASD 能用、拖鼠标毫无反应**"。菜单/设置用 `SetInputMode(UIOnly)` 时尤其要注意。

## 编辑器启动图陷阱(会被当成"你把关卡关了")

`EditorStartupMap` 决定编辑器每次启动打开的图。调 C++ 要关编辑器,重编后再打开就回到旧值 →
用户在某个关卡里测试时,会反复以为"关卡被关了"。→ **用户主要在哪个关卡测试,就把 `EditorStartupMap`
固定成那张图**;`GameDefaultMap` 是打包入口(主菜单),别动。

## 相机问题通用诊断法(本轮定了型)

`bFallbackCamDebugLog` 逐帧打印 `arm / raw / hit / pitch / camup / g / sup`:
- `arm` 长期贴着最小值 + `hit=` 某个 Actor → 空间挤死(先看那个 Actor 多大,再谈关卡);
- `camup` 不符合"世界 up + 俯仰"→ 姿态/朝退化(见上面两个真因);
- 要量偏航是否 1:1:用 `pivot→cam` 反推航向方位角,发固定角度再读差值。

## 双向"面吸附"的两个设计要点(2026-09-16,特殊滑梯1号)

1. **方向不用猜**:给定"入口面法线 → 出口面法线",令 `Axis = cross(EntryNormal, ExitNormal)`、`Tangent = Axis × 当前法线`,则沿 +Tangent 走**一定**是把接触法线往出口面转的那一侧(轴就是这么构造的)。所以镜像方向(平面→墙)不需要翻符号,只需要**方向门**挡住"反着滚"的球:`dot(Velocity, ApproachDir) >= 阈值`。反着滚的球在门这里被拒=正确行为,不要试图用速度大小区分。
2. **多件叠着摆时,触发盒会互相重叠 → 别把"打过了"记在组件自己身上**。实测:三个滑梯件叠着拼成一条,组件 A 刚把球送上墙的那一帧,组件 B/C 的触发盒同样罩着球,0.67s 后就把它反向吸回。**把守卫放到 Pawn 上做共享冷却**(`FaceCaptureReleaseCooldownSeconds = 0.5`,释放时记时间戳,`IsFaceCaptureCoolingDown()` 给所有件查),比"每个组件自己记"稳,也不会因为某个组件长期不复位而卡死玩家。
3. **"温和 vs 硬"两种吸附的取舍**(按玩家状态分流,用户原话"看人下菜"):球是**弹起来擦到面**的 → 硬吸附(进入瞬间换成定速沿面驱动,它本来就带着乱速度,定速才保证走完圆弧);球是**自己在地面上滚进来**的 → 温和吸附(切向保留球自己的速度、只钳到 [floor,ceil],法向只切掉"正在离开面"的分量),玩家不会被拽一下。判据用**入口面**(哪一面进)比用"空中时长"稳——"擦到"和"贴着滚"在接触瞬间的空中时长都接近 0,分不开。

## 凸圆弧"吸附"为什么会飞出去(2026-09-16 实测,两条机制)

做"把球摁在圆弧上带过去"这类效果时,两个隐蔽失效点(都会表现为"球跑太快就飞出去"):

1. **位置漂移不是速度能补的**:每帧 `SetPhysicsLinearVelocity(Tangent*v + Normal*小量)` 只保证
   *速度*没有朝外的分量,**位置**仍在按 `v²/ρ` 往外飘(900cm/s、ρ≈160 时 ≈0.7cm/帧)。
   按比例给法向速度(`-Gap*gain`,gain=8 只补 0.1cm/帧)追不上 → 球越飘越远。
   正解:**这一帧就把间隙合上**——`NormalSpeed = min(min(Vn,0), -Gap/Dt)`,再钳到速度上限;
   负间隙(压进面)时被 min 挡住,只收不放。
2. **探针的"只认自己人"会冻结整条状态机**:`if (Hit.GetActor() != MyActor) → 认为脱面` 在
   "球从自己的圆弧绕到相邻的墙/别的件"时必然触发——法线不更新、切向恒住,而出口判定要的是
   "法线转到出口面",于是永远不满足,球带着恒定切向速度被甩飞。
   正解:**连续性兜底**——命中的不是自己、但命中面法线与当前法线余弦 ≥ 阈值(实测 0.5 够用)
   就照常采用(`FaceCaptureSurfaceNormalMinDot`);再加一条"连续 N 秒完全探不到面就放开"的保险。
3. **中段入口的等价路程别算反**:如果入口不在"入口面法线"上(高速球一帧跨过平面、在圆弧中段被接住),
   要给重力旋转一个"已扫过弧长"的初值。记住 `acos(入口法线·出口法线)` 是**还剩**多少度,
   已扫过 = `90° − 它`。写反的后果是重力在进入瞬间跳掉大半(相机被猛拽),实测一眼就能看出:
   日志里 `entryAngle=79°` 而 `prog` 初值却是 158/180(≈87%)。
